# v2.4 Release Notes

## Real-Time Dashboard

- Flicker-free live updates via SSE + HTMX morphing (Idiomorph)
- Position card, analytics, and open orders refresh without DOM jitter
- Configurable refresh rate (`EXCHANGE_REFRESH_HZ`, default 1 Hz)

## Multi-Exchange Trading

- Binance USDM-M perpetuals (full trading)
- Bybit Linear perpetuals (full trading)
- MEXC read-only integration via adapter capability flags
- Vendor-neutral adapter protocol — adding an exchange means implementing
  two protocols, not modifying core

## History Page Redesign

- **3-card layout**: Open Positions, History tabs, Log tabs
- **Position History**: PnL%, Exit Reason badges (TP/SL/Trail/Manual/Liq),
  TP/SL prices, MFE/MAE, M-R ratio, granular hold times
- **Fill Drawer**: expand any closed position to see all underlying fills
  (entries + closes) with side coloring and PnL per fill
- **Execution Link**: tolerance-based matching of fills against pre-trade
  plan via calc_id — shows 3-criterion comparison (entry/TP/SL), user
  confirmable for partial matches
- **Trade Events Log**: chronological audit trail of 12 trade lifecycle
  events with badge-colored event types, payload summaries, and
  click-to-expand JSON detail
- **Trade History**: shows actual engine fills (auto-populated) instead of
  manual-entry-only table

## Account-Timezone-Aware Analytics

- Per-account timezone setting (configurable in UI)
- 7 analytics periods: weekly, monthly, quarterly, yearly, rolling 30d,
  rolling 90d, all-time
- Calendar date picker with preset ranges (Today/7d/15d/30d/90d)
- All time boundaries respect account timezone

## Risk Gating

- Rolling-window drawdown metric (replaces intraday-only DD)
- Strategy presets: scalping, day trading, swing, position — each seeds
  appropriate DD window, thresholds, and analytics defaults
- Shadow-mode enforcement rollout (advisory before enforced)
- Weekly loss caps and open-position limits

## Rate-Limit Architecture

- Weight tracker for exchange API budget management
- Fan-out coordination for parallel API calls
- Per-endpoint weight annotations prevent 429s

## Execution Quality

- `calc_id` propagation from calculator through orders, fills, and
  closed positions — enables slippage measurement and exec link matching
- Implementation shortfall computation (planned vs actual entry/exit)
- Slippage column on Trade History fills

## Observability

- `engine_events` audit trail (engine-level lifecycle)
- `trade_events` log (12 per-trade event types with structured payloads)
- System health monitoring (9 checks)

## Infrastructure

- InProcessBus (default) with optional Redis pub/sub backend
- Per-account database split for data isolation
- 10 schema migrations (001-010) applied automatically on startup
- 1247 automated tests
