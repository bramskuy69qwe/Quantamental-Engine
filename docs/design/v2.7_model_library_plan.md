# v2.7 — Model Library (Implementation Plan)

**Status:** design — pending execution.
**Created:** 2026-06-24
**Branch:** dedicated `v2.7/model-library` (land **after** v2.6 — see
[v2.6_remove_quantower_plugin_plan.md](v2.6_remove_quantower_plugin_plan.md)).
**Scope:** a DB-backed library of reusable, exchange-agnostic *models*, plus a per-app adapter

---

## 1. Context

A **model** is a reusable, exchange-agnostic trading definition the operator stores once and uses
anywhere. It carries:

1. **Identity / metadata** — name, type (`macro` / `micro` / `both`), description.
2. **Risk / sizing preset** — the calculator coefficients that don't change per-trade
   (risk %, sizing rule, window, TP/SL methodology, regime-multiplier toggle, size override).
3. **Strategy definition** — freeform notes + an opaque JSON config blob (entry/exit logic,
   target universe, regime config). Engine treats it as documentation; no execution semantics.
4. **Imported 3rd-party backtest runs** — performance results imported from external apps
   (MultiCharts first), 1 model : N runs, each with summary + trade list + equity curve.

**How a model is used** (operator decisions):
- **Pre-fill the calculator** — pick a model → its risk-preset loads into the risk calculator for
  any symbol/exchange.
- **Tag trades / linkage** — a plan records which model it came from; the model name surfaces in
  position history via the existing calc-linkage chain.
- **Reference catalog** — browse models + their imported backtest performance.

**What the engine does NOT do** (operator decision): it does **not** run backtests. Backtesting
is delegated to external apps; their results are **imported** (file upload, one adapter per app).
Import is **one-directional** (no export/round-trip to the external app). Models stay
**exchange-agnostic** — no symbol/exchange columns; exchange context is the active account at
calculator-use time.

### Storage decision (operator deferred to me): EXTEND `potential_models`, REUSE `backtest_*`
Avoids a duplicate "model" concept and a duplicated 3-table + mixin + renderer stack. The
MultiCharts adapter's normalized output maps **directly** onto the existing `backtest_trades` /
`backtest_equity` columns, so the existing insert helpers are reused unchanged.

Schema additions (idempotent `ALTER TABLE ... ADD COLUMN` in `database.initialize()`, each wrapped
in `try/except sqlite3.OperationalError` — the project's inline-migration pattern):
```
ALTER TABLE potential_models  ADD COLUMN risk_preset_json TEXT NOT NULL DEFAULT '{}'
ALTER TABLE potential_models  ADD COLUMN strategy_json    TEXT NOT NULL DEFAULT '{}'
ALTER TABLE potential_models  ADD COLUMN updated_at       TEXT
ALTER TABLE backtest_sessions ADD COLUMN model_id         INTEGER DEFAULT NULL
ALTER TABLE backtest_sessions ADD COLUMN source_app       TEXT NOT NULL DEFAULT ''
ALTER TABLE pre_trade_log     ADD COLUMN model_id         INTEGER DEFAULT NULL
CREATE INDEX IF NOT EXISTS idx_bt_sessions_model ON backtest_sessions(model_id)
```
- `risk_preset_json` — `{risk_pct, sizing_rule, window_seconds, tp_methodology, sl_methodology,
  apply_regime_multiplier, size_override_default}` (calculator pre-fill reads known keys).
- `strategy_json` — `{entry_logic, exit_logic, target_universe, regime_config, notes}`.
  (`config_json` stays for back-compat.)
- **Imported runs (1 model : N): reuse `backtest_sessions`** with nullable `model_id` +
  `source_app`. Imported runs set `model_id`; existing engine backtests + `qt-import` leave it
  NULL. Trades + equity reuse `backtest_trades` / `backtest_equity` unchanged; summary stats live
  in `summary_json`. Dedicated stat columns are deferred to v3 (only needed if cross-run SQL
  analytics is wanted — open item #4).
- **Calc FK:** `pre_trade_log.model_id` is the FK the free-text `model_name` becomes; the
  free-text columns stay (a model need not be selected).

## 3. Phasing rationale

Schema/DB first (no behavior change), then the parser, then API → UI → calculator wiring. Critical
path is **Phase 1 → 3 → 4**. Phase 2 (adapter) depends only on Phase 1's storage wrappers and can
proceed in parallel. Phase 5 (calculator pre-fill + tagging) depends on the `model_id` FK (Phase 1)
and the prefill route (Phase 3).

```
Phase 1: Schema + DB layer (extend potential_models, reuse backtest_*, model_id FKs)
  ├─> Phase 2: 3rd-party backtest adapter framework + MultiCharts (.xml + .xlsx)
  │
  └─> Phase 3: REST API (model CRUD + backtest import + prefill)   [needs 1 + 2]
        └─> Phase 4: Minimal UI (library page + fragments)
        └─> Phase 5: Calculator pre-fill + linkage tagging          [needs 1 + 3]
```

Effort tiers: **S** (≤1 day), **M** (2–4 days), **L** (>4 days).

### MultiCharts Strategy Performance Report — verified layout (sample: `@ES - 1 Minute`, 2026-06-24)
The export is an **OOXML workbook** (8 sheets, 273 shared strings). Detect by `PK` magic bytes →
`openpyxl`. Only three sheets carry the data the adapter needs:

| Sheet | Use |
|---|---|
| `Strategy Analysis` | summary stats (key in col A; **col B = All Trades**, C = Long, D = Short) |
| `List of Trades` | trade-by-trade list (header on row 2) |
| `Settings` | symbol, point value, compression, start/end date, initial capital + strategy params |
| `Trade Analysis` / `Periodical Analysis` | extra aggregates — optional |
| `Strategy/Trade/Periodical Analysis Graphs` (3) | chart images only — **no cell data** |

**Summary** (`Strategy Analysis`, col-A label → col-B value): `Net Profit` → net_profit;
`Gross Profit`/`Gross Loss` → gross; `Total # of Trades` → total_trades; `% Profitable` → win_rate
(fraction 0–1); `Max Strategy Drawdown` → max_drawdown **(absolute $)** + `Max Strategy Drawdown (%)`
→ max_drawdown_pct (fraction); `(Annualized) Sharpe Ratio` → sharpe (often `0` — MC didn't compute).
**Profit Factor gotcha:** MC reports it **signed-negative** (gross_profit ÷ *negative* gross_loss) —
compute `gross_profit/abs(gross_loss)`, don't trust the cell sign.

**Trade list** (`List of Trades`, header row 2):
`Trade # | Order # | Type | Signal | Date | Time | Price | Contracts | Profit ($) | Profit (%) | Cum. Profit ($) | Cum. Profit (%) | Run-up ($) | Run-up (%) | Drawdown ($) | Drawdown (%)`
- **Two rows per trade**: Entry row (`Type`=`EntryLong`/`EntryShort`; carries `Trade #` + the trade's
  `Profit ($)`/`Cum. Profit`/`Run-up`/`Drawdown`) then Exit row (`Type`=`ExitLong`/`ExitShort`; carries
  `Order #` + exit `Price`; profit cols blank). **Pair entry+exit** into one `BacktestTrade`.
- `side` ← entry `Type`; `entry_price`/`exit_price` ← the two `Price` cells; `pnl_usdt` ← entry
  `Profit ($)`; `exit_reason` ← exit `Signal` (`L_TP`→take_profit, `S_SL`→stop_loss, …);
  `r_multiple` not in the report (leave 0); `regime_label` n/a (MC has no regime).
- **Excel-serial dates** (epoch 1899-12-30); `Date` and `Time` hold the **same** datetime serial — use
  either, convert to ISO for `entry_dt`/`exit_dt`.

**Equity curve:** no dedicated equity *data* sheet (the `* Graphs` are images). Build it from the trade
list — per closed trade: `dt = exit_dt`, `equity = InitialCapital + Cum. Profit ($)`,
`drawdown = Drawdown ($)`.

**Settings sheet (bonus):** `Symbol Name` (@ES), `Point Value` ($50), `Compression` (1 Minute),
`Start/End Date`, `Initial Capital`, plus strategy params (`RiskPctOfEquity=1.0`, `RewardRiskMult=1.5`,
`ORMinutes=30`, …). These can optionally **seed** the model's `risk_preset_json` / `strategy_json` on
first import (open item #3a).
