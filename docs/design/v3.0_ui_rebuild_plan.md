## What this program is

v3.0 rebuilds the **presentation layer** of the engine against the Meridian v3.0
design reference — a high-contrast tiling "terminal" for the single-operator
localhost trading cockpit. The durable backend (model library, attribution,
reconciler, event bus) is shipped and stays; v3.0 replaces the Jinja/HTMX DOM.

Standing doctrine this program inherits (do not relitigate):
- **Track-2 / throwaway-DOM** (`HANDOFF.md:42-43`): today's DOM is disposable;
  browser-level tests come AFTER the new DOM stabilizes. Invest verification at
  the fragment/HTTP-contract + SSE-shape layer, not DOM selectors, until then.
- **Single-tenant localhost** (`CLAUDE.md` Deployment context): no auth/CSRF/SRI
  hardening is required at this shape; the operative concerns are correctness,
  observability, recovery — and now *offline determinism* (the SW precaches).
- **House cycle**: one commit per phase → targeted + full gate SOLO on the `.venv`
  interpreter → ≥1 independent read-only audit → fold findings → STOP for operator.
- **Deviations belong in plan executed-notes** (`CLAUDE.md`): annotate the plan
  row, not just the commit body, when shipped state diverges.

## §0 — The two gating decisions (operator must ratify before P0)

Everything downstream depends on these. The audit surfaced both as HIGH
[L5·H1, L3·Findings 2-3]. The plan RECOMMENDS; the operator RATIFIES.

### Decision A — Stack: adopt the React reference, or port its language into Jinja?

The design prompt forbade "a heavy SPA framework" and asked for server-rendered
Jinja/HTMX fragments [L5·H1, `v3.0_models_tab_design_prompt.md:76-79`]. The design
came back as a **React 18 SPA** whose identity *is* React-shaped: GridStack tiling
workspaces with drag/resize/persist, per-value `LiveValue` streaming with a
"target the value, never the pane" no-flicker contract, `PaneErrorBoundary`
self-heal, stateful modals, a tab-per-model strip. None of that is an HTMX idiom.

| | (A1) Port language into Jinja/HTMX + islands | (A2) Adopt React, serve static (RECOMMENDED) |
|---|---|---|
| Honors | the original prompt constraint | the delivered design's core interaction model |
| Cost | re-implement tiling/streaming/error-boundary by hand; lose the workspace identity | one-time AOT build step; new (vendored) runtime deps |
| Risk | a different, lesser product; large hand-port of ~9,300 lines of behavior | GridStack↔React DOM-ownership seam (provable in P0) |
| Toolchain | none new | offline esbuild/Babel-CLI prebuild, **no standing Node server**, **no `package.json` as a runtime dep** |

**Recommendation: A2 — adopt the Meridian React reference as v3.0's UI, served as
AOT-precompiled static JS from FastAPI.** Rationale: the prompt's constraint was
written *before* the design existed and its real intent was "don't force a
Node/webpack/SPA-router world onto a Python-only localhost shop." A2 satisfies
that intent — React production UMD + vendored deps + a one-shot precompile,
served static from `/static`, no dev server, no runtime `package.json` — while
keeping the design's identity (the tiling terminal) intact. The prompt's
"server-rendered fragments" constraint is formally superseded here; that
supersession IS the operator ratification this decision asks for.

*If the operator prefers A1*, the plan's phase sequence still holds but P0 changes
from "port primitives to JSX + precompile" to "port tokens+visual-language to Jinja
macros + build an islands layer for tiling/streaming," and the LiveValue/GridStack
findings become larger hand-builds. Flag this now — it roughly doubles P0.

### Decision B — Serving strategy (contingent on A2)

**Recommendation: precompiled static JS** [L3·Finding 3]. A one-shot offline
`esbuild` (or Babel-CLI) pass transpiles the 20 `text/babel` modules → plain `.js`,
concatenated in the existing dependency order [L3·Finding 8], served from
`/static/v3/`. Swap React **dev** UMD → **production** UMD. Vendor React, ECharts,
GridStack, and fonts into `/static/vendor/` and drop every CDN `<script>`/`<link>`
[L3·Finding 2] — this also closes the deferred MED-040 SRI item for the v3 surface
(local assets need no SRI) and makes the SW offline-precache honest. Keep
in-browser Babel ONLY as throwaway bring-up in P0.

Rejected: (i) ship in-browser Babel to production — multi-second cold boot, ~3 MB
Babel, React dev overhead; (ii) full Vite/webpack dev server — introduces the
standing Node toolchain + `package.json` the repo has deliberately never had
(confirmed: zero `package.json` anywhere in-repo).

## §1 — Architecture decisions (fold of Lens 3)

1. **Serving**: precompiled static JS under `/static/v3/`, mounted/served by
   FastAPI; a `/v3` route serves the shell HTML. (Decision B.)
2. **Live-data transport: SSE, no new WebSocket** [L3·Finding 4]. The engine
   already exposes `sse-starlette` streams (`api/routes_streams.py:49-81`) over the
   in-process `event_bus`, channels in `core/pubsub/channels.py:9-35`
   (`position_update`, `fill`, `order_update`, `equity_update`, `dd_state`,
   `weekly_pnl`) that map ~1:1 onto the design's `LiveValue` ids. Build a thin
   client adapter: one `EventSource` per active account that fans each coarse
   channel payload out to matching `data-live-id` spans (or a React context that
   re-renders only leaf `LiveValue`s). The browser-facing `ws_status` is the
   *exchange* WS health (htmx poll today) — do not confuse it with a UI socket.
   Keep htmx polling for coarse chrome during migration only.
3. **HALT-STATE AUTHORITY (HIGH) — fix in the port** [L3·Finding 1]. The design's
   `localStorage` "TRADING HALTED · positions frozen" banner is fiction: engine
   enforcement defaults **advisory (log-only)** and at most **blocks the
   calculator** — it is a pre-trade gatekeeper, never in the order path. Delete the
   `localStorage` halt *authority*; drive the banner from the real
   `account:{id}:dd_state` / `weekly_pnl` SSE channels; correct the copy to
   advisory-vs-enforced + "calculator blocked", never "positions frozen". Keep
   localStorage only for the cosmetic countdown. **This is a correctness fix, not a
   port fidelity choice — the mock must not ship as-is.**
4. **Vendored, offline-capable assets** [L3·Finding 2]: React production UMD,
   ECharts (reconcile 5.5.0 design vs 5.5.1 engine skew), GridStack, JetBrains
   Mono + Space Grotesk fonts — all local. Drop CDN tags. Update the service worker
   precache list to the vendored URLs; give `/v3` its own SW scope or no SW until
   stable [L3·Finding 5].
5. **Coexistence** [L3·Finding 5]: ship page-by-page behind `/v3/` alongside the
   live Jinja UI. Wire the active account id into the SSE URL from an engine
   bootstrap value (the React app currently has no account concept and would desync
   from `app_state.active_account_id`). Namespace workspace-layout localStorage keys
   by account [L3·Finding 6].
6. **Build-time load safety** [L3·Finding 8]: the AOT concatenation is where
   load-order / missing-module errors must surface (they are silent `undefined`s at
   runtime today). Concatenate in dependency order or move to ES modules.

### §3 — Exchange-agnostic vs. source-binding reconciliation (operator note)
[L5·H4, L1·H9] The design binds a model to `@ES`/point-value/commission; the prompt
+ shipped schema say models are exchange-agnostic. **Recommendation**: treat
symbol/point-value/commission/slippage as **per-run provenance** (they describe the
backtest, not the model) — store on `backtest_sessions` + the run's Settings, render
in the run report, and keep the *model* exchange-agnostic. The design's "Source"
block on the model Overview then reads through from the latest run rather than being
model-owned. This preserves the invariant while still surfacing the info. Flag for
ratification alongside §0.

## §8 — Testing doctrine (fold of Lens 3·7)

Track-2: no Playwright/DOM tests until `data-live-id` ids + page structure settle.
Interim verification at stable seams:
- Python tests that the SSE endpoints emit the expected channels/shapes.
- A test that `/v3` serves the shell + the precompiled asset manifest exists.
- One smoke test that boots the shell and asserts a single `LiveValue` updates from
  a seeded SSE event.
- Per-page: fragment/HTTP-contract tests for every new backend endpoint (§2).
Expand to DOM assertions only after the new DOM freezes.
