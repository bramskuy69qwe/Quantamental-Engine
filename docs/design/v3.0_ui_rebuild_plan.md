## What this program is

v3.0 rebuilds the **presentation layer** of the engine against the Meridian v3.0
design reference — a high-contrast tiling "terminal" for the single-operator
localhost trading cockpit. The durable backend (model library, attribution,
reconciler, event bus) is shipped and stays; v3.0 replaces the Jinja/HTMX DOM.

Standing doctrine this program inherits (do not relitigate):
- **Track-2 / throwaway-DOM** (`HANDOFF.md:42-43`): today's DOM is disposable;
  browser-level tests come AFTER the new DOM stabilizes. Invest verification at
  the fragment/HTTP-contract + SSE-shape layer, not DOM selectors, until then.
- **Single-tenant localhost** (`CLAUDE.md` Deployment context): no auth/CSRF/SRI
  hardening is required at this shape; the operative concerns are correctness,
  observability, recovery — and now *offline determinism* (the SW precaches).
- **House cycle**: one commit per phase → targeted + full gate SOLO on the `.venv`
  interpreter → ≥1 independent read-only audit → fold findings → STOP for operator.
- **Deviations belong in plan executed-notes** (`CLAUDE.md`): annotate the plan
  row, not just the commit body, when shipped state diverges.

## §0 — Gating decisions — RATIFIED 2026-07-22

Everything downstream depended on these. The audit surfaced both as HIGH
[L5·H1, L3·Findings 2-3]. **Operator ratification (2026-07-22):**
- **Decision A → A2** — adopt the React reference, served as AOT-precompiled static
  JS. ("do the best if you think react works more efficient then use it.")
- **Decision B → precompiled static JS** + vendored offline assets (contingent on A2).
- **§3 → REVERSED**: models carry source binding (backtest provenance); exchange-

The original recommendation write-up is kept below for the record.

### Decision A — Stack: adopt the React reference, or port its language into Jinja? [RATIFIED → A2]

The design prompt forbade "a heavy SPA framework" and asked for server-rendered
Jinja/HTMX fragments [L5·H1, `v3.0_models_tab_design_prompt.md:76-79`]. The design
came back as a **React 18 SPA** whose identity *is* React-shaped: GridStack tiling
workspaces with drag/resize/persist, per-value `LiveValue` streaming with a
"target the value, never the pane" no-flicker contract, `PaneErrorBoundary`
self-heal, stateful modals, a tab-per-model strip. None of that is an HTMX idiom.

| | (A1) Port language into Jinja/HTMX + islands | (A2) Adopt React, serve static (RECOMMENDED) |
|---|---|---|
| Honors | the original prompt constraint | the delivered design's core interaction model |
| Cost | re-implement tiling/streaming/error-boundary by hand; lose the workspace identity | one-time AOT build step; new (vendored) runtime deps |
| Risk | a different, lesser product; large hand-port of ~9,300 lines of behavior | GridStack↔React DOM-ownership seam (provable in P0) |
| Toolchain | none new | offline esbuild/Babel-CLI prebuild, **no standing Node server**, **no `package.json` as a runtime dep** |

**Recommendation: A2 — adopt the Meridian React reference as v3.0's UI, served as
AOT-precompiled static JS from FastAPI.** Rationale: the prompt's constraint was
written *before* the design existed and its real intent was "don't force a
Node/webpack/SPA-router world onto a Python-only localhost shop." A2 satisfies
that intent — React production UMD + vendored deps + a one-shot precompile,
served static from `/static`, no dev server, no runtime `package.json` — while
keeping the design's identity (the tiling terminal) intact. The prompt's
"server-rendered fragments" constraint is formally superseded here; that
supersession IS the operator ratification this decision asks for.

*If the operator prefers A1*, the plan's phase sequence still holds but P0 changes
from "port primitives to JSX + precompile" to "port tokens+visual-language to Jinja
macros + build an islands layer for tiling/streaming," and the LiveValue/GridStack
findings become larger hand-builds. Flag this now — it roughly doubles P0.

### Decision B — Serving strategy (contingent on A2)

**Recommendation: precompiled static JS** [L3·Finding 3]. A one-shot offline
`esbuild` (or Babel-CLI) pass transpiles the 20 `text/babel` modules → plain `.js`,
concatenated in the existing dependency order [L3·Finding 8], served from
`/static/v3/`. Swap React **dev** UMD → **production** UMD. Vendor React, ECharts,
GridStack, and fonts into `/static/vendor/` and drop every CDN `<script>`/`<link>`
[L3·Finding 2] — this also closes the deferred MED-040 SRI item for the v3 surface
(local assets need no SRI) and makes the SW offline-precache honest. Keep
in-browser Babel ONLY as throwaway bring-up in P0.

Rejected: (i) ship in-browser Babel to production — multi-second cold boot, ~3 MB
Babel, React dev overhead; (ii) full Vite/webpack dev server — introduces the
standing Node toolchain + `package.json` the repo has deliberately never had
(confirmed: zero `package.json` anywhere in-repo).

## §1 — Architecture decisions (fold of Lens 3)

1. **Serving**: precompiled static JS under `/static/v3/`, mounted/served by
   FastAPI; a `/v3` route serves the shell HTML. (Decision B.)
2. **Live-data transport: SSE, no new WebSocket** [L3·Finding 4]. The engine
   already exposes `sse-starlette` streams (`api/routes_streams.py:49-81`) over the
   in-process `event_bus`, channels in `core/pubsub/channels.py:9-35`
   (`position_update`, `fill`, `order_update`, `equity_update`, `dd_state`,
   `weekly_pnl`) that map ~1:1 onto the design's `LiveValue` ids. Build a thin
   client adapter: one `EventSource` per active account that fans each coarse
   channel payload out to matching `data-live-id` spans (or a React context that
   re-renders only leaf `LiveValue`s). The browser-facing `ws_status` is the
   *exchange* WS health (htmx poll today) — do not confuse it with a UI socket.
   Keep htmx polling for coarse chrome during migration only.
3. **HALT-STATE AUTHORITY (HIGH) — rewire to real state + freeze Pre-Trade**
   [L3·Finding 1, L2·G2; operator directive #3]. The design's `localStorage`
   "TRADING HALTED · positions frozen" banner is fiction: engine enforcement defaults
   **advisory (log-only)** and, in enforced mode, at most **blocks the calculator** —
   it is a pre-trade gatekeeper, never in the order path, so "positions frozen" is
   impossible for it to enact. Delete the `localStorage` halt *authority*; drive the
   state from the real `account:{id}:dd_state` / `weekly_pnl` SSE channels + the
   account's enforcement mode (`/api/state`; add a `halted`/`blocked` boolean to
   `/api/state` — G-O2, none exists today). **Correct manifestation:**
   - **enforced mode + limit breached → BLOCK THE CALCULATOR VISUALLY.** Apply a
     **blur + freeze overlay over the entire Pre-Trade page's panes**. **Concrete
     attachment (verified against the reference):** the Pre-Trade `<GridWorkspace>` at
     `pages.jsx:470` wraps exactly the 7 panes (nav/header/refresh-strip/footer sit
     outside it) and already forwards a `style` prop onto its scroll-wrap div
     (`grid-workspace.jsx:131`) — so gate it with
     `style={{filter: blocked?'blur(3px) grayscale(0.4)':'none', pointerEvents:
     blocked?'none':'auto', userSelect: blocked?'none':'auto'}}` and render an
     absolutely-positioned sibling scrim + reason card ("calculator blocked · DD 30d
     > 10% cap") in a `position:relative` wrapper around it. Also flip the header
     `GATE` StatusDot (`pages.jsx:445`) to blocked and dim the `✓ LINKABLE` countdown
     strip (`:463`). The server-side calculator gate already rejects the submit; the
     overlay makes that state legible and un-actionable.
   - **advisory mode + breach → warning banner only, no freeze** (advisory = log-only;
     trading continues; the banner informs, does not block).
   - **Driver:** replace the hardcoded `const halt = null` (`pages.jsx:433`) + the
     duplicate "positions frozen" fictions (the Pre-Trade `<Banner>` at
     `pages.jsx:453-455` **and** the notification banner `notifications.jsx:148`) with
     the real `dd_state`/`weekly_pnl` SSE + a `halted` flag on `/api/state` (G-O2), and
     read the Advisory-vs-Enforced mode from the account's **DD Enforcement Mode**
     select (`ConfigPage`, `pages.jsx:1649`). Keep `localStorage` only for a cosmetic
     countdown if any. **This is a correctness fix, not a port choice — the mock must
     not ship as-is (it appears TWICE).**
4. **Vendored, offline-capable assets** [L3·Finding 2]: React production UMD,
   ECharts (reconcile 5.5.0 design vs 5.5.1 engine skew), GridStack, JetBrains
   Mono + Space Grotesk fonts — all local. Drop CDN tags. Update the service worker
   precache list to the vendored URLs; give `/v3` its own SW scope or no SW until
   stable [L3·Finding 5].
   → **P0 SHIPPED**: ECharts **5.5.1** vendored (engine parity — the 5.5.0/5.5.1
   skew is resolved); React/ReactDOM prod UMD + GridStack + both fonts vendored
   local (`static/vendor/`), all CDN tags dropped. **SW deferral (P1/coexistence)**:
   base.html's root-scoped, cache-first SW still controls `/static/*`, so the
   *unhashed* `/static/vendor/*` deps can be stale-served on a same-name re-vendor
   until `CACHE_NAME` bumps (the hashed app/tokens/shell are safe — network-first
   HTML + content-hashed filenames). Scoping `/v3` away from that SW (or hashing
   vendored files) + pruning the SW's now-dead CDN host list is deferred to the
   coexistence phase — not a P0 blocker (`/v3` isn't promoted to `/` yet).
5. **Coexistence** [L3·Finding 5]: ship page-by-page behind `/v3/` alongside the
   live Jinja UI. Wire the active account id into the SSE URL from an engine
   bootstrap value (the React app currently has no account concept and would desync
   from `app_state.active_account_id`). Namespace workspace-layout localStorage keys
   by account [L3·Finding 6].
6. **Build-time load safety** [L3·Finding 8]: the AOT concatenation is where
   load-order / missing-module errors must surface (they are silent `undefined`s at
   runtime today). Concatenate in dependency order or move to ES modules.

## §2 — Data-contract gaps (fold of Lens 1 + Lens 2)

The design renders more than the backend serves. Gaps are the backend work that
must land **in the phase before** the UI that consumes them [L6 placement rule].

### Models (Lens 1) — the parser is the critical path
The single biggest gap: the MultiCharts adapter reads only cols A/B of one sheet
and keeps ~9 scalars, discarding most of what the design renders — **all
parseable from the file the operator already uploaded** [L1·H1-H7]. Backend work,
in dependency order:
- **G-M1 (FOUNDATIONAL) — per-run report store + endpoint** [L1·H6]: add
  `report_json` (or a `model_backtest_report` table) + `GET
  /api/models/{id}/runs/{run_id}/report`. **This store holds the VERBATIM workbook
  capture (G-M2), not a distilled summary** — every sheet, every cell, structure-
  and type-preserving. Everything in Screen C rides this.
- **G-M2 — generic lossless workbook capture (the efficient "render as is")**
  [L1·H1-H5,H7,M5; operator directive #4, clarified 2026-07-22: "the file reader
  should read ALL aspects of the imported 3rd-party (MultiCharts) file"]. **"Render as
  is" = lossless INGESTION of the whole file, not pixel-mimicry of MultiCharts' own
  layout.** The efficient architecture — do NOT enumerate MultiCharts' metric taxonomy
  into a typed schema (that path is high-effort, fragile, and permanently incomplete):
  1. **Raw capture — generic, complete, dumb.** One serializer walks EVERY sheet →
     `{sheet_name, rows: [[cell, …], …]}`, preserving each cell's raw value + type
     (number / date / string) + SIGN, dumped verbatim into `report_json` (G-M1).
     Capture is NOT gated by what the design renders — keep everything the file holds,
     even data the current design has no pane for (cheap; future-proofs the report).
     This one mechanism satisfies BOTH "read all aspects" and "render as is".
  2. **Derived normalized aggregate — thin, semantic, EXISTING.** The current adapter's
     ~9 summary scalars + `backtest_trades` + equity curve STAY, but become a *derived*
     aggregate computed from the captured workbook (feeding the library leaderboard /
     calc-prefill / cross-model KPIs — G-M3). This layer does not grow.
  3. **Render from the raw grids.** Sheet → tab, grid → table. The design's bespoke
     sub-tabs (All/Long/Short grid, ratios block, Trade Analysis, hourly Periodical,
     per-trade Run-up) become a **label-lookup at render time** against the captured
     cells — NOT a parser concern; degrades gracefully if a label moves (the raw grid
     survives). Sheets with no bespoke pane fall back to a generic sheet-table view.
  **The one correctness leak to guard:** preserve enough per-cell type info for the UI
  to format — number vs date vs string, and the SIGN (MultiCharts reports Profit
  Factor + drawdown signed-negative). `openpyxl(data_only=True)` yields typed cells;
  capture the raw value and ideally the number-format string [L1·L1,L2].
  **Retire the "only 3 sheets carry data" assumption** (`multicharts.py:9-11`): generic
  capture reads ALL sheets regardless — that assumption only ever governed which sheets
  the *derived aggregate* reads. Storage is a non-issue — these reports are KB-scale
  (the synthetic fixture is 10 KB).
- **G-M3 — library/overview feed** [L1·H8]: extend `/api/models` (or add
  `/api/models/overview`) to embed each model's latest-run KPIs + a downsampled
  equity sparkline + a leaderboard aggregate. Avoids N+1.
- **G-M4 — source binding + tags on the model — RATIFIED IN** [L1·H9,M3, §3]:
  `source_json` + `tags_json` columns on `potential_models` + form/API fields +
  auto-seed source from a parsed import's Settings sheet (§6-3b [L5·M1]). Model owns
  its source (the account is the exchange-agnostic entity, not the model).
- **G-M5 — import preview + create-plus-import** [L1·M1,M2]: `?dry_run=1`
  parse-preview endpoint returning KPIs+warnings without writing; a combined
  create-model-and-import endpoint (or create-if-absent on upload).
- **G-M6 — usage/attribution reverse feed** [L1·M4, L5·M2]: `GET
  /api/models/{id}/usage` — reverse lookup across `pre_trade_log`/`closed_positions`
  (+ live positions for status:open). Data exists; only forward calc→model helpers
  do today.
- **G-M7 — small stores** [L1·M6,M7]: persist the imported filename; store contract
  count alongside `size_usdt`.
