# v3.0 UI plan audit — Meridian design reference vs. shipped engine

**Date**: 2026-07-22
**Branch**: `v3.0/ui-plan-audit`
**Design reference imported at**: `docs/design/meridian_v3/` (commit `5a24c66`)
**Method**: 6 parallel read-only agents, each a distinct lens, over the imported
Meridian v3.0 React reference + the shipped v2.7 backend. This ledger is the
source document for `docs/design/v3.0_ui_rebuild_plan.md`; findings are folded
into that plan (house precedent — the v2.7 rev-2 plan folded 24 audit findings
before execution).

**Lenses**
1. Models data contract (design Models pages ↔ shipped model/backtest backend)
2. Other-pages data contract (Dashboard/Linkage/Analytics/Regime/History/Config)
3. Architecture & feasibility (prototype runtime → production serving + transport)
4. Design internal consistency + mock-data traps
5. Planning-doc staleness + scope reconciliation
6. Phasing + execution risk

Severity is **for v3.0 planning**, not runtime bug severity: HIGH = the plan must
explicitly decide/resolve it; MED = should note; LOW = cosmetic / note-only.

## Cross-cutting headlines (read first)

- **STACK CONTRADICTION (the #0 decision).** The design prompt forbade "a heavy
  SPA framework" and mandated FastAPI+Jinja+HTMX server-rendered fragments
  (`v3.0_models_tab_design_prompt.md:76-79`); the delivered Meridian reference is
  a **React 18 SPA** (`meridian_v3/DESIGN.md:4`). The plan cannot proceed
  page-by-page until this is resolved. (Lens 5 · H1, Lens 3 · rec.)
- **SCOPE EXPANSION.** Prompt asked for **one tab** (Models); the design delivered
  the **whole 9-page app** as a cohesive system. Re-scope to "v3.0 presentation
  rebuild, Models first." (Lens 5 · H2)
- **HALT-STATE AUTHORITY CONFLICT (HIGH).** The design persists a "TRADING HALTED
  · positions frozen" banner in `localStorage` with a client-side countdown
  (`notifications.jsx:111-129,148`), but the engine's drawdown/weekly enforcement
  defaults to **advisory (log-only)** and at most **blocks the calculator** — it is
  a pre-trade gatekeeper, never in the execution path, so "positions frozen" is
  impossible for it to enact. The banner is fiction. (Lens 3 · Finding 1)
- **THE BIGGEST DATA GAP IS THE PARSER, NOT THE UI.** The Meridian Models surface
  renders a full MultiCharts-shaped report per run (All/Long/Short grid, 8 ratios,
  Trade Analysis, hourly Periodical, per-trade run-up). The shipped adapter reads
  only columns A/B of one sheet and keeps ~9 scalars — most of what v3.0 shows is
  **parseable from the file the operator already uploaded but discarded before it
  reaches the DB**. (Lens 1 · H1–H7)
- **PREMISE CORRECTION.** The Linkage needs-link **per-criterion match diff already
  has a full backend** (`routes_orders.py:524-557` + `core/calc_correlation.py` +
  `match_audit`). Linkage's real gap is the richer lifecycle-cockpit *fields* the
  design mocks, not the diff engine — an additive endpoint sub-task, not a blocker.
  (Lens 6 · Finding 0)
- **SERVING + TRANSPORT RECOMMENDATION.** Precompile JSX → static JS served from
  FastAPI `/static` (offline esbuild/Babel-CLI, React **production** UMD, vendor
  every CDN dep) — NOT a standing Node dev-server, NOT shipping in-browser Babel
  beyond throwaway bring-up. Live data over **SSE** (the engine already exposes
  `sse-starlette` streams whose channels map ~1:1 onto the design's `LiveValue`
  ids); add no browser-facing WebSocket. (Lens 3 · Findings 2–4)

## Lens 3 — Architecture & feasibility

**Recommendation up front:** AOT-precompile JSX → static JS served from FastAPI
`/static` (offline esbuild/Babel-CLI; React **production** UMD; vendor every CDN
dep locally) — not a standing Node/Vite dev-server (the repo is deliberately
Python-only, zero `package.json` anywhere — confirmed), and not the in-browser
Babel build beyond throwaway bring-up. Live data over **SSE** (engine already has
it; `LiveValue` is documented SSE-targetable). Biggest risk is **authority**, not
rendering: the localStorage halt banner is fiction.

- **1 · HIGH — Halt-state authority conflict.** Design banner is client-owned +
  simulated (`notifications.jsx:111-129`, releases at next UTC midnight, hardcodes
  "positions frozen" `:148`). Engine enforcement defaults **advisory (log only)**
  and only ever "blocks the calculator" (`docs/config.md:35-38`,
  `core/auth_state.py`); it is a pre-trade gatekeeper (`config.py:46`), never in the
  order path. → delete the localStorage halt *authority*; drive the banner from the
  real `account:{id}:dd_state` / `weekly_pnl` SSE channels
  (`core/pubsub/channels.py:25-30`); correct copy to advisory-vs-enforced +
  "calculator blocked" not "positions frozen". Keep localStorage only for the
  cosmetic countdown.
- **2 · HIGH — CDN runtime deps contradict localhost/offline doctrine + PWA
  precache.** React dev UMD + ECharts + `@babel/standalone` + GridStack + Google
  Fonts across 4 CDNs (`Meridian v3.0.html:8-19`); doctrine is localhost-only,
  SRI-deferred *because* of it (`CLAUDE.md:415-428`); the SW now precaches for
  offline (`static/service-worker.js:20-24`) and even tries to cache the CDN hosts
  (`:78-87`) — offline is impossible while deps are remote. SRI is only partial in
  the prototype (ECharts + both GridStack tags carry no `integrity=`). → vendor
  every runtime asset into `/static/vendor/` (React **production** UMD), drop CDN
  tags; closes MED-040 for the v3 surface (local assets need no SRI); reconcile the
  ECharts version skew (design 5.5.0 vs engine base.html 5.5.1).
- **3 · MED — Serving strategy.** In-browser Babel transpiles 20 files every load
  (the boot splash exists to mask it, `Meridian v3.0.html:87-137`); tolerable only
  as throwaway bring-up. Precompiled static JS keeps the window-global module
  pattern + load order, drops Babel, enables React production UMD, adds no Node
  dev-server. Full bundler = best output but introduces the `package.json` the repo
  never had. → **precompiled static JS**.
- **4 · MED — Live-data transport.** Browser-facing realtime is SSE, not WS
  (`api/routes_streams.py:49-81` `EventSourceResponse`, backed by `event_bus`,
  channels in `core/pubsub/channels.py:9-35`). No browser-facing WebSocket exists
  (`app_state.ws_status` is the *exchange* WS health, exposed via htmx polling).
  Mismatch: engine SSE emits coarse per-channel JSON; `LiveValue` wants per-
  `data-live-id` updates. → SSE + a thin client adapter (one EventSource per active
  account, fan each channel payload out to matching `data-live-id` spans / a React
  context re-rendering only leaf LiveValues). Keep htmx polling for coarse chrome
  during migration only. Add no WebSocket.
- **5 · MED — Coexistence seams.** A `/v3/` static-shell mount alongside Jinja is
  feasible page-by-page (React app is self-contained, hash-routed), but: SW scope
  is `/` with a single cache (`base.html:993-997`, `main.py:275-281`) → could serve
  stale cross-app HTML; single PWA `start_url:'/'` can't point at both shells; the
  React app has **no account concept** and would desync from
  `app_state.active_account_id` (`base.html:513-528`). → ship behind `/v3/` with its
  own SW scope (or no SW until stable), a separate manifest if installed-PWA is
  wanted, and wire the account id into the SSE URL from an engine bootstrap value.
- **6 · MED — State persistence.** Workspace layouts/lock/page in localStorage are
  fine client-side (`grid-workspace.jsx:146-196`) but keys are global (no per-
  account namespace); combined with Finding 1 the halt key is the one piece that
  must move server-side. → namespace workspace keys by account; move halt authority
  to the engine.
- **7 · LOW — Testing doctrine (Track-2).** "today's DOM is throwaway; browser
  tests come AFTER the new DOM stabilizes" (`HANDOFF.md:42-43`). Suite is 4119
  Python/pytest, no JS test tooling. → verify at stable seams (SSE endpoints emit
  expected channels/shapes; `/v3/` serves the shell; asset manifest exists); one
  smoke test that boots the shell + asserts a live value updates from a seeded SSE
  event; defer Playwright/DOM until ids + structure settle.
- **8 · LOW — Window-global wiring + fixed load order fragile.** Any reorder or
  missing file silently breaks downstream modules with no resolution error
  (`DESIGN.md:7`); primitives are built "for portability into htmx templates"
  (`primitives.jsx:4`). → the AOT precompile is the point to concatenate in
  dependency order (or move to ES modules) so load-order errors surface at build.

## Lens 6 — Phasing + execution risk

**Premise correction (Finding 0, HIGH):** the Linkage per-criterion diff HAS a
backend (`routes_orders.py:524-557` + `core/calc_correlation.py` + `match_audit`);
`/fragments/needs_link` already renders it. Linkage's real gap is the richer
lifecycle-cockpit fields the design mocks (per-calc tags/op/r/model in
`link-data.jsx`) — additive endpoint work, not a phase blocker.

**Ground truth:** design = 9 pages, ~9,300 JSX lines, zero build step; two
disjoint token systems that can't co-mingle in one document (base.html
`#07080f`/`border-radius:5px` vs. `--qe-*` pure-black/no-radius) → each React page
must be a full-page island. Coexistence is structurally cheap (nav is one
server-driven `nav_items` list + `page_meta` dict; every Jinja page is a full
document). Coupling gradient by template size: calculator 1100 · regime 953 ·
history 448 · backtest 416 · analytics 196 · cockpit 122 · config 87 · dashboard
67 · **model_library 35** (thinnest). base.html carries ~1,293 lines of cross-page
plumbing (toast/error surface, notif poll, operator-session heartbeat, steppers,
ECharts dispose-on-swap, tab switchers, ws-status poll) that React islands lose.

**Recommended phase sequence** (foundation-first, then one page per phase in
ascending coupling / ascending live-data dependency; one commit per phase; old
Jinja serves until each React page is operator-accepted):
- **P0 — Foundation & serving decision** (no prod page): make the build/serve call
  (vendor deps + esbuild prebuild; in-browser Babel throwaway only); port the
  shared layer once (`tokens.css`, `primitives.jsx`, `charts.jsx`+theme,
  `grid-workspace.jsx`); stand up a React host shell (NOT base.html) at `/v3`
  rendering the **Primitives page** as the proving ground; decide port-vs-bridge
  for base.html's shared plumbing. *Accept:* `/v3` serves Primitives from vendored
  (non-CDN) assets, offline-capable; GridStack drag/resize/persist works in a React
  tree; ≥1 ECharts chart renders from `QE_ECHARTS_THEME`.
- **P1 — Models** (first real page — the v3.0 charge): lowest coupling, the
  design's centerpiece, the only fully-briefed page, and **request/response only**
  (CRUD + upload) → does NOT depend on the unproven live-data transport. Sub-gated:
  1a Library → 1b Detail+Form+Delete → 1c Run report + Import flow. *Accept:*
  operator completes every Models JTBD on `/v3/models` against real data (incl.
  importing a real MultiCharts `.xlsx`); Jinja `/models` stays live as parity ref.
- **P2 — Live-data transport spike + Dashboard** (highest visibility): solve
  streaming first (prove `LiveValue` "target the value not the pane" against real
  SSE), then rebuild the 1s-polling Dashboard.
- **P3 — Regime + Analytics** (chart-heavy, read-mostly, no money-path writes).
- **P4 — History + Linkage** (attribution surfaces): minimal queue already backed;
  the additive backend work (lifecycle fields) lands one step ahead of the UI.
- **P5 — Calculator** (the coupling monster — deliberately last): full wiring
  (submit, prefill from the React Models page, window/refresh, countdown, supersede,
  `?model_id=`); re-derive the countdown/PENDING mechanism per CLAUDE.md
  re-investigation discipline (the FE-HIGH-009 race) rather than porting it.
- **P6 — Config + Jinja retirement + JS-drift sweep**: design Config just-in-time;
  retire each Jinja template, re-host/retire base.html plumbing, promote `/v3` → `/`;
  run the CLAUDE.md post-primitive-migration grep for OLD classes across
  templates/static/inline scripts.

**Backend-work placement rule:** every data-gap endpoint lands in the phase
*before* its consuming UI. No UI phase gates on an undesigned API.

**Top risks (ranked):** R1 big-bang/dual-system divergence (CRIT) · R2 live-data
transport unproven in React (CRIT) · R3 in-browser Babel + no toolchain (HIGH) ·
R4 GridStack+React DOM-ownership conflict (HIGH) · R5 calculator rebuild complexity
(HIGH) · R6 mock-data fidelity gaps (MED) · R7 primitive-surface scope explosion
(MED) · R8 operator single-user acceptance loop (MED) · R9 base.html shared-plumbing
loss (MED) · R10 Config thin in the design (MED) · R11 post-migration JS-drift
(LOW-MED) · R12 in-flight-Phase pattern extension (LOW-MED). Mitigations in the
plan.

**Explicit defer list:** notification sound/desktop; news ticker; workspace presets
beyond the default; Primitives-page productization (it's the P0 proving ground);
layout alternates (dash-tape/dash-command/dash-split-rail/pages-regime-v2);
creative-latitude extras (cross-run comparison, tags/collections, library
sparklines); Settings-sheet auto-seed mapping surface (keep read-only render);
light-mode (dark-only).

## Lens 2 — Other-pages data contract

*Legend: (a) SERVED · (b) DERIVABLE (data exists, new/reshaped endpoint) · (c) NOT
SERVED (new endpoint/event) · (d) MOCK-ONLY (do not build).*

**Headline:** the backend already serves the overwhelming majority of the
non-Models surface — Pre-Trade, History, all 4 Regime tabs, Config
accounts/connections, and **9 of 11 Analytics tabs** are fully backed, and the
Linkage cockpit (positions, calcs, needs-link diff, manual-link actions,
manual-close reason enum — enum parity confirmed) is wired end-to-end. This makes
P2–P6 far less backend-heavy than feared. **The 3 biggest genuine gaps: D1 Engine-Log
live feed, A1/A2 Analytics Execution-Quality + Distributions tabs, L1 Linkage
