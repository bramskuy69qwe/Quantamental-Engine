### ★ The fix-review pass changed two fixes materially — read this before trusting the finding text

A 5-lens adversarial review ran on the fixes before commit and returned
**3 DO-NOT-SHIP / 2 SHIP-WITH-NITS, 24 findings (0 CRIT, 3 HIGH)**. Two are
calibration-grade:

1. **`shell-chrome-3` named the WRONG SOURCE.** The finding (and the first fix)
   used `app_state.ws_status.connected` as market-feed health. It is the
   **user-data** socket: `ws_manager` writes `connected` only in
   `_user_data_loop` (`:529`/`:621`) and `stop()`; the market loop (`:755`/`:795`)
   only logs. `ws.last_update` is worse — both loops stamp it AND the 30 s REST
   account refresh floors it, so the advertised half-open detection could never
   fire. As first written the dot would have lied **in both directions**: red
   "prices frozen" on a user-socket blip, green through a real market outage.
   Fixed by adding genuine market-socket tracking (`market_connected` /
   `market_last_update` / `market_latency_ms` + `market_seconds_since_update`)
   and pointing the endpoint at those. **The filed symptom was real; the
   mechanism it named was not** — the audit-impact-imprecision pattern, this
   time inside an audit finding rather than a spec.
2. **`config-1`'s first fix INTRODUCED a way to write an inverted risk config.**
   `validate_params` gates warn<limit on BOTH keys being present and validates
   the SUPPLIED subset, not the merged result — so "blank = keep stored" let the
   operator clear one half, skip the cross-check, and store `warn >= limit`
   behind a 200 "Saved.". Not cosmetic: the weekly pair is consumed
   unconditionally and the limit branch evaluates first, so an inversion deletes
   the entire warning tier. Fixed by posting each pair atomically (blank half
   backfilled from stored) plus a client-side pre-check that keeps the rejection
   out of the endpoint's write-before-validate window.

Also folded: a fabricated `0ms` latency (the legacy Jinja fragment's falsy guard
had not been carried over); `_navFeed` ignoring `ch.stateErr` (the dot would stay
green after the engine died — the same defect class the finding was about);
REST-fallback showing a frozen websocket latency as current; Pre-Trade's
200-with-no-price case painting health over a latched stale sizing price; and
**a revert of this pass's own TRIGGER fallback**, which printed an entry order's
take-profit PLAN level as if it were that order's trigger and desynced the column
from its own sort.

Two false claims in the new UI copy were caught and corrected: the DD ratios are
read ONLY in the rolling-DD `except` fallback (the primary path uses the absolute
`account_settings` thresholds), and `PRESET_PARAMS` carries no ratios at all, so
a preset does not rewrite them.

**Lesson for the next cycle**: an audit finding's cited SOURCE deserves the same
independent verification as a spec's recommended fix. Two of five fixes needed
material correction after passing a green gate — the tests could not see either,
because both were true-to-the-source-they-read and wrong about which source to
read.

instructed to judge structure/affordances/IA/interaction semantics, never numbers, and
the following were pre-excluded as not-findings:

- Anything whose only design content was fabricated data (P8 wave 1 killed that class).
- The build having MORE than the design (real error states, data-state foots, retries).

  real `exit_reason`; models-report `tools={false}` for verbatim-capture fidelity.
