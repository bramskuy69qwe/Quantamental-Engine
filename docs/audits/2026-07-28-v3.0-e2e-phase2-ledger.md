## E2E-P2-001 — CRIT — `period=all_time` 500s every analytics door (+ silently empty stats)

**Symptom (collector)**: clicking the ALL period button →
`GET /fragments/analytics/overview?format=json&period=all_time` → HTTP 500; five
Analytics panes degrade to `server error (500) · showing last data`. Reproduced
deterministically with a direct GET pre-fix.

**Mechanism (investigated, not assumed)**: `resolve_period('all_time')`
(`core/period_resolver.py:104`) returns `start = datetime.min` (year 1, tz-aware).
`_analytics_range` (`api/routes_analytics.py:93`) converted it to
`from_ms = -62_135_620_924_000`. Downstream, `core/db_analytics.py:331`
(`get_r_multiples`) runs `datetime.utcfromtimestamp(from_ms/1000)` — outside the
platform `gmtime()` range on Windows → `OSError`. `get_r_multiples` is called
OUTSIDE the route's `return_exceptions` gather → 500. The gathered calls
(`db_analytics.py:64/124`, same conversion) failed too but were swallowed →
**All-Time journal stats silently rendered empty** — the quieter half of the defect.

**Why it survived until now**: the legacy Jinja ALL button sends `all=1`
(`from_ms=0` path); only the v3 React PeriodSelector sends `period=all_time`.
The resolver's other caller (`routes_dashboard.py:254-255`) passes only
quarterly/yearly — the class is contained to `_analytics_range`.

**Fix (shipped)**: clamp at the producer — `from_ms/to_ms = max(0, …)` in
`_analytics_range` — the exact semantics of the legacy `all=1` path. One site cures
the 500 AND the silent stats degradation for every analytics fragment door.
Pins: `tests/test_analytics_alltime_range.py` (4). Suite: 46 green
(new pins + test_routes).

**Live verification pending engine restart** (running engine predates the fix;
`--reload` is off by design). Re-run of the sweep after restart is the gate.

**Positive observation folded in**: under the 500, all five panes held last-good
data with truthful `server error (500) · showing last data` feet — the qeFootState
tier-2 degradation path works as designed under a real backend failure.

## E2E-P2-002 — harness — ElementHandle detach race (20 action errors)

16/20 were the DataList search-input restore step: typing the probe re-renders the

panes (Pre-Trade segment after mode switch, Regime tab content, Config 30 s poll).

element on detach and retries (`withRefind`). Also fixed this run:
`describe.serial` skipped 98 tests after the first failure; outcomes now persist
to disk per test (worker restarts wipe module state) and `.serial` is removed.
